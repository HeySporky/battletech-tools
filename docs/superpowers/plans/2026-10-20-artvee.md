# ArtVee Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build, rate, print and play the ArtVee (Custom Homebrew transforming tracked artillery tank) in the Combat
Vehicle creator, with the canon Armored Motive System and the *Future Wars* #32 smoke devices it relies on.

**Architecture:** The ArtVee is a Combat Vehicle flag, modelled on the FrankenVehicle (`src/classes/vehicle.ts`
1213-1345): state and hooks live in `Vehicle`, and the ArtVee rules (validation, notes, the combo-gun lookups) live
in a new sidecar module `src/classes/vehicle-artvee.ts` that reads the vehicle through its public API. The combo
guns are ordinary equipment records that name their canon artillery piece (`comboArtilleryTag`), so Siege Mode stats
always come from the canon record. Armored Motive is a canon Combat Vehicle chassis modification.

**Tech Stack:** TypeScript, React 18 class components, Vitest (`npm test` = `vitest run --project unit`).

**Spec:** `docs/superpowers/specs/2026-10-20-artvee-design.md`. Read it before starting any task.

**Branch:** `feature/artvee` (cut from `feature/home-status-oct16` at afc6c19a).

## Global Constraints

- Every custom record has `rulesLevel: 6`, `book: "Custom"` (or the fanzine name for the smoke devices) and is
  never offered below rules level 6 (`isEquipmentWithinRulesLevel`).
- New catalogs go in the target layout: `src/data/artillery-custom.ts`, `src/data/misc-custom.ts`,
  `src/data/ammo-custom.ts`, `src/data/combat-vehicle-chassis-modifications-custom.ts`. No record goes into a legacy
  `mech-*` file. Each record has `techBase` right after `tag`.
- Catalogs are literal object arrays, registered in `src/data/equipment-registry.ts`.
- Never invent a stat, date, citation or page. Where a step says "read the page image", enter only what the page
  shows; if the page can't be read, stop and ask the user.
- No MegaMek/SSW writer exists for vehicles today; nothing in this plan writes one. The app's JSON save must
  round-trip every ArtVee field.
- 4-space indentation; tests next to the source; each rules test names its rule ("TO:AUE p.94" or
  "ArtVee design 2026-10-20").
- Never run `npm run deploy-prod`. Commit only on the user's go-ahead for this plan; never push upstream.
- Verification baseline for every task: `npm test`, `npm run typecheck` and `npm run lint` all pass.

## Review Focus

1. **Chassis changed under an ArtVee** (motive set to wheeled, turret removed, Support Vehicle toggled, tonnage over
   100): the flag drops or an issue shows; nothing throws; the combo gun is listed as an issue, not silently
   deleted. Test: Task 5, "drops the ArtVee when the vehicle stops being a tracked Combat Vehicle".
2. **Old and foreign saves:** a save without ArtVee fields loads as an ordinary vehicle; a save with
   `artVee: true` on a wheeled vehicle loads with an import issue and no ArtVee. Test: Task 5, "imports".
3. **Tech base of custom records:** a Clan vehicle is offered only the Clan combo guns, an IS vehicle only the IS
   ones, a mixed-tech vehicle both; untagged custom records still reach everyone. Test: Task 2.
4. **Armored Motive out of era:** mounting it is refused before its dates; a design loaded or re-dated into an
   earlier era shows an issue rather than keeping it silently. Test: Task 3, "is refused outside its dates".
5. **Siege Mode in play:** 0 MP, but not immobile (no −4 to hit it); the combo gun can't fire during a
   transformation turn; destroyed conversion equipment strands the mode. Test: Task 8.

  - The combo gun isn't in `turret`.
