# E-War Phase 0 (Audit and Skeleton) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every unit class can tell the E-War layer what E-War gear it carries and save its E-War state; every rules
edition (Classic and Alpha Strike) says which E-War items its books print, with book and page; the catalog has every
E-War item each edition prints; the force holds an E-War board whose entries write onto units with per-field hand
overrides. No play effect yet: that is Phases 1-5.

**Architecture:** One new rules module `src/utils/ewar-play.ts` on the `quirk-effects.ts` pattern (a structural
carrier shape any unit class satisfies, pure functions). Edition data extends `src/data/rules-editions.ts`. Unit
state follows `BattleMech.futureWarsPlay` (optional in export, cleared by `noInPlayVariables`). The force board extends
`BattleMechForce` and reuses `c3Networks`.

**Tech Stack:** TypeScript, React 18, Vitest (run in PowerShell only).

**Spec:** `docs/superpowers/specs/2026-11-20-ewar-play-design.md` (commit 8acef5829). Issue #642.

## Global Constraints

- Every rules edition, every unit type, every time (memory every-edition-every-rule.md). Never TW-only.
- Condense and extend: the only new source file is `src/utils/ewar-play.ts` (and its test file, as no test file covers
  a new module); everything else extends existing files and existing test files.
- Rules and item data are read from the book's page image, never memory or OCR text. Find with
  `py -3.11 -I library_search.py "<words>" --books` (from `C:/repo/ResourceLibrary`), render with
  `py -3.11 -I render_page.py "<pdf>" --find "<text>" text/<book>.txt out.png`, read the PNG. A garbled extract page is
  rewritten in `text/<book>.txt` and logged in `text/_corrected_pages.md`; keep a CRLF file CRLF (binary Python
  replace for mixed-ending files). ResourceLibrary commits: never the other agent's files.
- Saves: every new field optional in every export shape; old saves load with empty E-War state.
- Vitest in PowerShell: `npx vitest run --project unit <path>`.
- Catalog fixes that move BV or cost are allowed when the book says so; list each in the phase notes and news bullet;
  rebuild the bundle.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` (or the model that did the work).

## Review Focus

1. A destroyed or damaged E-War item: `getEWarGear()` reports it with `destroyed: true`, never drops it silently
   (Phase 1 needs "ECM destroyed" to stop the bubble). Test in Task 3.
2. An old save with no `ewarPlay` / `ewarBoard`: loads, exports nothing new, round-trips unchanged. Tests in Tasks 3,
   4, 5, 6 and 7.
3. A board entry naming a unit no longer in the force (removed after the entry was made): ignored on apply and
   dropped on export, as `c3Networks` already does. Test in Task 7.
4. A hand override on a field, then the board entry that sets it is removed: the override clears and the field goes
   back to unset. Test in Task 7.
5. An edition with no `ewarPlayRules`: `getEWarPlayRules` returns undefined and every module function returns empty.
   Test in Task 2.

### Tasks 8-12: The catalog audit (research; one task per family)

Each audit task, for its family, for **every** Classic edition in `btRulesEditions` and every Alpha Strike edition:

1. Search the library for each item's play rule and construction entry (`library_search.py ... --books`), render and
   read the page images.
2. Record a row per item in the design doc's new appendix **"Appendix A: E-War item matrix"** (append to
   `docs/superpowers/specs/2026-11-20-ewar-play-design.md`; condense rule): kind, catalog tags, per edition the play
   rule's book and page (or "not in this edition"), unit types that can carry it (TM/TO tables and each edition's own),
   and any difference between editions in one line.
3. Fill `ewarPlayRules.items[kind] = { book, page }` on each edition that prints the rule (Task 2's test now checks
   real entries).
4. Fix the catalog where it disagrees with the book: missing item -> add the record (in the file its family uses:
   `equipment-misc.ts`, `equipment-missile.ts`, `*-custom.ts` for fan items, BA/infantry files), with its `editions`
   list; wrong `editions` list or stats -> fix. Each fix gets a test in the file that already tests that catalog
   (`catalog-editions.test.ts`, `equipment-registry.test.ts`, or the family's test file), watched fail first. Add any
   new kind to `EWarKind`, `getEWarKind` and its test.
5. Write back garbled extract pages and log them (Global Constraints).
6. Commit per family: "E-War audit: the family (#642)"; ResourceLibrary extract fixes committed and pushed separately.
